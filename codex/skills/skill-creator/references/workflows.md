# 工作流模式

## 顺序型工作流

如果任务较复杂，优先拆成明确的顺序步骤。通常适合在 `SKILL.md` 前部先给一个过程总览：

```markdown
处理一个 PDF 表单通常按以下步骤进行：

1. 分析表单
2. 创建字段映射
3. 验证映射
4. 执行填充
5. 检查输出
```

## 条件分支型工作流

如果任务会根据输入分叉，先明确分支判断，再写各自步骤：

```markdown
1. 先判断任务类型：
   - 创建新内容 -> 走“创建流程”
   - 修改现有内容 -> 走“编辑流程”

2. 创建流程：...
3. 编辑流程：...
```

关键点不是“写得很长”，而是让后续执行者清楚知道自己此刻应该走哪条路径。
