# 部署指南

本指南涵盖 DeerFlow App 的所有支持部署方式：本地开发、Docker Compose，以及使用 Kubernetes 管理沙箱的生产环境部署。

## 本地开发部署

本地工作流是运行 DeerFlow 的最快方式。所有服务都以本机原生进程运行。

<Tabs items={["启动", "停止", "日志"]}>
  <Tabs.Tab>
```bash
make dev
```

启动的服务：

| 服务        | 端口 | 说明                    |
| ----------- | ---- | ----------------------- |
| LangGraph   | 2024 | DeerFlow Harness 运行时 |
| Gateway API | 8001 | FastAPI 后端            |
| Frontend    | 3000 | Next.js 前端界面        |
| nginx       | 2026 | 统一反向代理            |

访问地址：**http://localhost:2026**

  </Tabs.Tab>
  <Tabs.Tab>
```bash
make stop
```

停止上述四个服务。即使某个服务当前未运行，也可安全执行。

  </Tabs.Tab>
  <Tabs.Tab>
```
logs/langgraph.log   # Agent 运行时日志
logs/gateway.log     # API Gateway 日志
logs/frontend.log    # Next.js 开发服务日志
logs/nginx.log       # nginx 访问/错误日志
```

实时查看日志：

```bash
tail -f logs/langgraph.log
```

  </Tabs.Tab>
</Tabs>

## Docker Compose 部署

Docker Compose 会在容器中运行所有服务。适用于更接近生产环境的本地部署，或团队协作环境。

### 前置条件

- 已安装 Docker（macOS 可使用 Docker Desktop 或 OrbStack）
- 仓库根目录下已配置 `config.yaml`

### 开发环境 Compose

```bash
# 设置 deer-flow 仓库根目录的绝对路径
export DEER_FLOW_ROOT=/path/to/deer-flow

docker compose -f docker/docker-compose-dev.yaml up --build
```

服务包括：nginx、frontend、gateway、langgraph，以及可选的 provisioner（用于 K8s 管理沙箱）。

访问地址：**http://localhost:2026**

### 环境变量

在仓库根目录创建 `.env` 文件，用于存放密钥和运行时配置：

```bash
# .env
OPENAI_API_KEY=sk-...
DEER_FLOW_ROOT=/absolute/path/to/deer-flow
```

`docker-compose*.yaml` 文件通过 `env_file: ../.env` 自动加载该文件。

<Callout type="warning">
  生产环境请务必设置强随机 `AUTH_SECRET`。如果未设置，前端构建将使用公开已知的默认值，存在安全风险。
</Callout>

### 数据持久化

线程数据存储在 `backend/.deer-flow/threads/`。在 Docker 部署中，此目录会被 bind mount 到 langgraph 容器。

为避免容器重建导致数据丢失：

1. 将 `DEER_FLOW_ROOT` 设置为仓库根目录的绝对路径（或稳定的宿主机路径）。
2. 确认 `threads/` 与 `skills/` 目录挂载正确。

生产环境建议使用命名卷（named volume）或 PVC（Persistent Volume Claim），而不是宿主机 bind mount。

## 生产部署注意事项

### 沙箱模式选择

| 沙箱模式                               | 适用场景                   |
| -------------------------------------- | -------------------------- |
| `LocalSandboxProvider`                 | 单用户、受信任的本地工作流 |
| `AioSandboxProvider`（Docker）         | 多用户、中等隔离需求       |
| `AioSandboxProvider` + K8s Provisioner | 生产环境、强隔离、多用户   |

任何并发用户数大于 1 的部署，都建议使用容器化沙箱，避免用户之间执行环境互相干扰。

### K8s Provisioner 配置

Provisioner 负责在 Kubernetes 集群中管理沙箱 Pod，`docker/docker-compose-dev.yaml` 已包含该服务。

<Steps>

#### 配置 Provisioner

在 `.env` 或 compose 覆盖配置中设置以下环境变量：

```bash
K8S_NAMESPACE=deer-flow
SANDBOX_IMAGE=enterprise-public-cn-beijing.cr.volces.com/vefaas-public/all-in-one-sandbox:latest
DEER_FLOW_ROOT=/absolute/path/to/deer-flow
```

#### 配置沙箱提供器

```yaml
# config.yaml
sandbox:
  use: deerflow.community.aio_sandbox:AioSandboxProvider
  provisioner_url: http://provisioner:8002
```

#### 配置持久化存储

生产环境中请使用 PVC 替代 hostPath：

```bash
# 在 .env 或 compose environment 中
USERDATA_PVC_NAME=deer-flow-userdata-pvc
SKILLS_PVC_NAME=deer-flow-skills-pvc
```

设置 `USERDATA_PVC_NAME` 后，Provisioner 会自动使用 `subPath`（`threads/{thread_id}/user-data`），使每个线程在 PVC 中拥有独立目录。

</Steps>

### nginx 配置

nginx 负责路由全部流量。关键路由环境变量如下：

| 变量                 | 默认值           | 说明                          |
| -------------------- | ---------------- | ----------------------------- |
| `LANGGRAPH_UPSTREAM` | `langgraph:2024` | LangGraph 服务地址            |
| `LANGGRAPH_REWRITE`  | `/`              | LangGraph 路由的 URL 重写前缀 |

这些变量通常在 Docker Compose 环境中设置，并在容器启动时由 `envsubst` 处理。

### 认证配置

DeerFlow App 使用平台认证服务进行会话管理。生产环境建议先生成强随机密钥：

```bash
# 生成随机密钥
openssl rand -base64 32
```

### 资源建议

| 服务                      | 最低配置         | 推荐配置         |
| ------------------------- | ---------------- | ---------------- |
| LangGraph（Agent 运行时） | 2 vCPU, 4 GB RAM | 4 vCPU, 8 GB RAM |
| Gateway                   | 0.5 vCPU, 512 MB | 1 vCPU, 1 GB     |
| Frontend                  | 0.5 vCPU, 512 MB | 1 vCPU, 1 GB     |
| 沙箱容器（每会话）        | 1 vCPU, 1 GB     | 2 vCPU, 2 GB     |

## 部署后验证

启动后可执行以下检查：

```bash
# 检查 Gateway 健康状态
curl http://localhost:8001/health

# 检查 LangGraph 健康状态
curl http://localhost:2024/ok

# 通过 nginx 查看配置模型（验证完整代理链路）
curl http://localhost:2026/api/models
```

若部署正常，每个端点应返回 `200`；`/api/models` 会返回 `config.yaml` 中配置的模型列表。
