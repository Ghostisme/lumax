# 浏览器验收本地推项目管理 Skill

## 背景

用户要求先阅读巨量引擎开放平台 `https://open.oceanengine.com/labels/37/docs/1807977111009572?origin=left_nav` 开发文档，然后对每个接口创建高覆盖测试用例，并通过真实浏览器执行测试；测试失败时必须修复 bug 后重新测试，不得通过指定空工具、不调用真实接口、脚本直连或其它降低难度的方式通过验收。

官方 `doc_id=1807977111009572` 是“项目管理模块”目录页，正文为空，但文档树显示该目录当前包含 16 个子接口。本地 `oceanengine-local-project` 已在 `references/index.md` 与 `rules/index.json` 中覆盖这 16 个接口，并通过 `oceanengine_local_project` 原生业务工具执行参数校验、MCP payload 构造、受管理 MCP 调用和中文结果展示。

现有规格已经要求 `oceanengine-local-project` 页面验收覆盖原生业务工具真实路径，并要求 Pydantic 改造完成后通过浏览器自然语言验收；但还不足以约束“按接口逐接口高覆盖浏览器用例矩阵”：

- 未要求 16 个官方项目管理接口逐接口建立浏览器用例矩阵。
- 未区分创建、更新、批量变更、详情查询、列表查询和依赖型查询的覆盖维度。
- 未明确测试输入必须模拟真实用户表达，不能点名 `oceanengine-local-project`、`oceanengine_local_project`、capability、底层 MCP tool 或 JSON tool payload。
- 未明确正向调用、负向校验、平台业务失败和环境失败的计数边界。
- 未把“测试失败后修复并重新测试”固化为逐用例状态规则。
- 未体现最新要求：每个接口不指定固定测试用例数量，应围绕该接口的字段、枚举、条件依赖和边界条件尽可能覆盖。

## 目标

- 为 `oceanengine-local-project` 建立浏览器自然语言验收计划，覆盖官方“项目管理模块”当前 16 个接口。
- 在实际执行前先形成逐接口高覆盖测试用例矩阵；矩阵不设固定用例数量，而是按每个接口的规则字段、必填、条件必填、条件禁止、枚举、类型、数组、分页、金额、长度、时间、批量项和依赖数据链尽可能覆盖边界条件。
- 使用测试账号的本地推账号 `1854708763953159` 执行浏览器验收；浏览器登录信息仅用于本轮测试，不写入 OpenSpec 文档或验收记录。
- 要求主验收必须通过浏览器对话页面触发真实 Agent 路径、`oceanengine_local_project` 原生业务工具路径和真实 MCP 接口调用路径。
- 对创建、更新、状态批量更新和投放时段批量更新类接口，使用测试环境可造数据策略，优先创建带时间戳前缀的测试项目并在后续用例复用。
- 发现工具未选择、校验绕过、MCP guard 绕过、平台调用失败、结果展示异常、认证失败或环境缺失时，先定位根因并修复，再重新执行受影响接口的用例组。

## 非目标

- 提案阶段不修改功能代码、运行时配置、skill 文件或测试实现。
- 不改变 `oceanengine-local-project` 的 16 个接口范围、字段语义、MCP tool 绑定或官方文档同步规则。
- 不把直接 Python dry-run、curl、HTTP API、SDK 或 MCP 直连作为浏览器验收成功标准；这些只能作为失败定位的辅助证据。
- 不在 OpenSpec 文档、验收记录、日志摘要或提交信息中落盘登录密码、Cookie、token、浏览器本地存储值或其它敏感凭证。
- 不要求所有平台业务数据必须非空；列表接口返回空列表时，只要真实接口调用成功、中文展示正确且证据完整，仍可作为读取类正向用例通过。

## 影响范围

- OpenSpec 规格：`oceanengine-local-project-template-migration` 的浏览器验收要求。
- Apply 阶段验收记录：用于保存测试矩阵、执行轮次、线程或 trace、工具调用证据、真实 MCP 调用证据、用户可见中文结果、失败根因、修复文件和重测结果。
- Apply 阶段可能涉及的修复范围：工具注册、skill 导航、自然语言参数整理、规则校验、字段映射、MCP guard、结果压缩、前端对话发送链路、Gateway 认证或本地运行环境配置。

## 风险与约束

- 浏览器输入不得包含 `oceanengine-local-project`、`oceanengine_local_project`、`capability`、`payload_json`、`dry_run`、底层 MCP tool 名、脚本路径或“直接调用某工具”等提示。
- 正向用例必须证明进入真实业务调用；不得通过传空工具、mock 成功、只做本地校验、不发送接口请求或伪造工具结果通过测试。
- 参数必须多样化。同一接口的新用例如果只重复完全相同的账号、项目、门店、商品、分页、排序、时间、枚举或批量数组组合，不得作为新增覆盖证据。
- 用例数量不设固定上限或下限；只有当该接口已声明规则、官方边界和可执行业务路径均有覆盖证据时，才能认为矩阵准备充分。
- 环境阻断不能算接口失败，也不能算正向成功；环境恢复后必须重新执行受影响用例。
- 平台业务失败需要分层记录：如果失败源于测试数据不满足官方业务前置条件，应调整测试数据后重测；如果失败源于代码 bug，应修复后重测；如果平台服务返回稳定内部错误，应保留真实调用证据并标记为平台失败，不得伪造通过。
