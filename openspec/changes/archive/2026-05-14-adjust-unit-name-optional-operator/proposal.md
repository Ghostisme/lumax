# 调整项目与单元默认命名规则

## 背景

本地推创建项目流程当前会按业务默认生成单元名称：`yyyyMMdd` + 地域 + 定向类型 + 年龄 + 投手姓名首字母大写。用户确认希望在拿不到投手姓名时，不再为单元名称追加投手首字母，也不使用 `X` 之类的兜底后缀。

当前代码中 `build_default_unit_name()` 会把 `operator_name` 转为首字母，并且未知中文字符会 fallback 为 `X`。创建项目流程仍有“投手优先追问”的既有规则，本次变更只收窄单元名称生成逻辑：当名称生成环节没有可用投手姓名时，默认名称应省略投手后缀。

用户进一步确认：项目名生成规则应与单元名一致，且项目名和单元名一般保持一致。因此默认项目名和默认单元名应共用同一套业务命名规则；当用户没有显式提供项目名或单元名时，两者应默认一致。

## 变更内容

- 调整 `oceanengine-local-unit-management` 中“创建项目后单元名称必须按业务默认生成”的规格。
- 明确单元名称格式中的投手首字母是可选部分：只有拿到非空 `operator_name` 时才追加。
- 明确缺少投手姓名时不得追加 `X`、`--`、`未知`、`None`、`null` 或其它占位符。
- 保持品牌自定义 `unit_name` 覆盖默认规则。
- 在 `oceanengine-local-project-template-migration` 中新增默认项目名规则：项目名默认使用与单元名相同的 `yyyyMMdd` + 地域 + 定向类型 + 年龄 + 可选投手首字母。
- 当用户没有显式提供 `name` 和 `unit_name` 时，项目名与单元名 SHALL 默认一致。
- 当用户只显式提供项目名 `name` 时，单元名 SHALL 默认复用项目名；当用户显式提供 `unit_name` 时，单元名 SHALL 以 `unit_name` 为准。

## 非目标

- 不改变素材管理、项目管理和单元管理的 MCP tool 边界。
- 不新增前端交互。
- 不把投手姓名作为 `localProjectCreate` 官方 payload 字段透传。
- 不引入拼音库或完整中文姓名转拼音能力。
- 不调整视频数量、素材库候选、出价方式等其它创建项目规则。
- 不增加新的品牌命名模板系统；本次只处理默认项目名与默认单元名的一致性。

## 风险

- 如果仍有代码路径把缺失投手姓名提前阻断，则实现阶段需要确认该阻断是否只属于创建流程补齐顺序，避免误改为所有路径都强制要求投手。
- 如果测试只覆盖有投手场景，可能漏掉空字符串、缺字段、`None` 等无后缀场景。
- 如果 `name` 和 `unit_name` 的覆盖优先级不清晰，可能导致用户显式指定项目名后单元名仍按旧规则自动生成，造成项目和单元命名不一致。
